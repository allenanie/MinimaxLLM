# Adversarial prompting against LLM agents: datasets, attack corpora, benchmarks, harnesses

## 1. Orientation

The field splits into four attack families.
Direct prompt injection and jailbreaking put the adversarial text in the user turn, which is the classic chat setting and where the optimizer literature (GCG, PAIR, TAP, AutoDAN) lives.
Indirect prompt injection (IPI) puts the adversarial text in content the agent reads as data: web pages, emails, file contents, tool return values, issue trackers, README files, config files, and tool or skill descriptions ([InjecAgent](https://arxiv.org/abs/2403.02691), [AgentDojo](https://arxiv.org/abs/2406.13352)).
Agentic misuse asks whether a jailbroken agent can still *complete* a harmful multi-step task, which is a capability question rather than a refusal question ([AgentHarm](https://arxiv.org/abs/2410.09024)).
Supply-chain style attacks target the agent's own configuration surface: poisoned MCP tool descriptions ([MCPTox](https://arxiv.org/abs/2508.14925)) and poisoned skill files ([Skill-Inject](https://arxiv.org/abs/2602.20156), [MalSkillBench](https://arxiv.org/abs/2606.07131)).

Agent red-teaming differs from chat jailbreaking in three ways that matter for harness design.
First, success is a state change (a tool called with attacker-chosen arguments, a file written, a secret exfiltrated) rather than a text judgement, so the harness needs a sandbox and a programmatic checker instead of an LLM refusal judge; [b3](https://ukgovernmentbeis.github.io/inspect_evals/evals/safeguards/b3/) scores tool-invocation matching, and [RedCode](https://github.com/AI-secure/RedCode) and [OS-Harm](https://github.com/tml-epfl/os-harm) require Docker and a VM respectively.
Second, the attack must survive an end-to-end pipeline (be retrieved, evade a detector, produce a correctly formatted tool call), which is why [LLMail-Inject](https://arxiv.org/html/2506.09956v1) reports much lower success rates than single-turn corpora at comparable effort.
Third, utility and security trade off inside one run, so benchmarks report a task-completion number alongside attack success rate, and over-defense is a measured failure mode ([AgentDyn](https://arxiv.org/html/2602.03117v1) finds most existing defenses are either insecure or over-defensive).
The practical consequence is that static jailbreak corpora transfer poorly, whereas *attack templates plus an environment plus a checker* transfer well, and the strongest recent results come from adaptive attackers who see the defense ([The Attacker Moves Second](https://arxiv.org/abs/2510.09023) breaks 12 defenses to above 90% ASR).

## 3. Worth a deeper look later

1. **`inspect_evals/ipi_coding_agent` (CodeIPI)**, and the `agentdojo` + `b3` ports beside it: MIT, one runner, Docker sandboxes, and injections placed in issue text, code comments, README and `pyproject.toml`, which is precisely the untrusted-input surface a terminal-coding harness exposes.
2. **Skill-Inject**: it attacks the agent's instruction surface (`SKILL.md`) rather than its tasks, on Claude Code / Codex / Gemini CLI, and already ships evolutionary and RL optimization ablations, making it the nearest existing instance of the adversary role described for this project.
3. **AgentDojo plus AgentDyn as a pair**: AgentDojo's pipeline abstraction with a pluggable defense slot and paired utility/security scores is the API shape to copy, and AgentDyn (MIT fork) shows what breaks when tasks become open-ended and defenses become over-defensive.
4. **BenchJack**: the only found artifact that attacks Terminal-Bench/Harbor itself, both by trojanizing unprotected system binaries and by injecting hidden instructions into an unsanitized LLM-judge prompt; the judge-injection half is directly a harness-prompt-surface attack.
5. **AutoInject ("Learning to Inject") and AgentVigil**: the two clearest recipes for an automated adversary against agents, one RL with a comparison-based dense reward, the other MCTS fuzzing over injection templates, both benchmarked on AgentDojo so results are comparable.
6. **LLMail-Inject dataset**, and **MalSkillBench** beside it: the former is 462k MIT-licensed human adaptive attacks against a defended end-to-end pipeline (the best empirical prior on what survives retrieval plus a detector plus tool-call formatting), and the latter's Generate-Verify-Feedback loop with Docker syscall-level runtime verification is a working design for an adversary whose proposals must be *verified* effective rather than merely judged.

## 4. Rejected / chat-only

- **AdvBench** (inside [llm-attacks](https://github.com/llm-attacks/llm-attacks)): 520 single-turn harmful-behavior strings with no environment, no tools, and no state-change checker; fully subsumed by HarmBench and JailbreakBench for any purpose here.
- **jailbreak_llms / "Do Anything Now"** ([verazuo/jailbreak_llms](https://github.com/verazuo/jailbreak_llms)): 15,140 scraped prompts and 1,405 labeled jailbreaks, static corpus plus a response judge, no attack loop and no agent interface; the prompts target chat refusal, not tool calls.
- **Tensor Trust** ([paper](https://people.eecs.berkeley.edu/~russell/papers/iclr24-tensor.pdf)): 126k attacks and 46k defenses from an online game, but the game is prompt hijacking and prompt extraction against a two-string defense, with no tools or environment.
- **HackAPrompt**: 600k+ competition prompts against three chat models, valuable as attack-phrasing vocabulary only; there is no agent, no tool surface, and no execution.
- **Lakera `gandalf_ignore_instructions`**: single-turn "ignore previous instructions" injections against a filter game; superseded for our purposes by the same vendor's b3, which at least models tools and agent state.
- **StrongREJECT** ([dsbowen/strong_reject](https://github.com/dsbowen/strong_reject), the successor to the deprecated `alexandrasouly/strongreject`): 313 forbidden prompts plus an autograder, i.e. a prompt-and-single-response scoring harness with no attack generation and no agent target.
- **safetyprompts.com**: useful catalog of 149 safety datasets with licenses, but it is archived (no longer updated as of May 2025), scoped to chat safety, and does not tag agent-specific artifacts; the [agent-safety benchmark taxonomy paper](https://arxiv.org/html/2605.16282v1) (40 benchmarks, 2023-2026) is the better index now.
- **AgentSafety / OSU-NLP** ([OSU-NLP-Group/AgentSafety](https://github.com/OSU-NLP-Group/AgentSafety)): surfaced repeatedly in searches but I could not confirm what it ships or under what license, so it is parked as unverified rather than surveyed.
